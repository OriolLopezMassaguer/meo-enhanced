# 文档表面配色方案

状态：已确认并接入第一版，派生强度等待视觉验收继续调整。

## 目标与边界

维持八项可配置基础色。新增的文档背景与界面背景独立；代码块、公式、表格和
frontmatter 使用少量共同派生角色，不为每种元素增加颜色设置。用户选定的文档底色
保持原值，派生色不持久化。外围菜单、设置、表格弹层继续使用 UI 表面体系。

Live 是正文表面迁移的主要范围。Source 的普通源码区域保持文档底色及原生语法前景，
不把 Live 的块卡片背景强加到 Source。默认 Preview 沿用其明暗匹配与文档跟随关系；
独立 Preview 预设保持自己的完整配色。后续接入 Preview 和导出时通过已有样式环境
传递最终角色，不让 Host 和 Webview 分别推导两套值。

## 现状证据

- `webview/src/helpers/uiTheme.ts` 统一解析八项基础色并校正 UI/内容强调前景。
- `webview/src/helpers/theme.ts` 将旧正文主题语义写入 CSS；其中代码块与行内代码底色
  仍由 `src/shared/builtInVisualBaseline.ts` 提供，行内代码存在独立固定值。
- `webview/src/styles.css` 的代码块、Mermaid 容器、块状公式编辑源码共用
  `--meo-code-background`，已有可复用关系；公式阅读状态通常保持透明。
- frontmatter 当前将文档背景与旧表格边线混合，活动行另设混合比例。
- 表格边线、水平分割线、引用边线、键盘标签边线在旧正文语义中分别定义；
  块按钮还有单独的浅深色固定灰色和旧工具栏悬停色。
- Preview 和导出另有正文表面派生，直接修改 Live CSS 不能完成全范围一致性。

## 共同角色与元素映射

以文档背景 B 为起点。角色数量不是新增配置数量；角色只是八项输入的计算结果。

| 共同角色 | 复用位置 | 视觉关系 |
| --- | --- | --- |
| 文档底色 | Live、Source、目录；同明暗默认 Preview | 用户输入原值，或解析后的默认值 |
| 行内弱表面 | 行内代码、行内公式编辑提示、属性标签底色 | 与 B 接近，比普通文字所在区域略易识别 |
| 块表面 | 代码块、Mermaid 外层容器、块状公式编辑区及编辑结果、frontmatter | 同一基础层级，主要靠留白、圆角和弱底色区分 |
| 表格弱表面 | 表格表头、浮动表头、隔行填充 | 共用同一个最终色，从 B 独立派生；不另选色 |
| 正文分隔线 | 水平分割线、表格网格、引用边线、列表引导线、块内分隔线 | 同一色系，按用途分弱/普通强度；线宽和位置仍由元素决定 |
| 编辑边界 | 拖动把手、需要辨识的编辑轮廓、可操作边界 | 比分隔线强；焦点仍来自操作强调色 |
| 块内操作前景与交互底色 | 复制、全选、折叠、模式切换、语言标签、缩放、全屏入口 | 中性前景按实际块表面校正；常态透明，悬停/按下使用块表面的派生状态 |

行内公式阅读状态继续与文字融为一体，不给每个公式永久增加色块。
键盘标签 `<kbd>` 保持无填充，只保留边框和按键外形。
块状公式阅读结果保留现有透明呈现；编辑状态才与代码块共用块表面。
frontmatter 的布局、语法颜色、属性标签含义保持原样，改变容器/标签底色及边界来源。
Mermaid 外层承载面和默认连线标签底色应共同跟随块表面；后者目前也进入
`themeVariables.background` / `edgeLabelBackground`，不能只修改外层 CSS 就宣称
已适配。作者声明的节点、连线及分类图表颜色保持原样。默认节点/分组表面、边线
和文字的整体迁移先单独审查对比与图表含义，不在本轮自动全部重染。

## 派生方法与辨识度

1. 先解析基础色与实际承载面，再计算相邻层级。优先使用现有 OKLab 混色及对比
   校正能力；不为此次迁移引入新的颜色库，不以主题名称维护特例。
2. 以实际背景明度决定减淡或加深方向。浅色背景通常向深色少量混合，深色背景通常
   向浅色少量混合；模式用于选择配置和强度，不能取代对实际底色的检查。
   保持背景色系，不从操作强调或内容强调给大面积正文块染色。
3. 行内区域面积小，可比大块表面略明显；增加轻内边线辅助辨识，避免强填充。
   表头/隔行填充使用比行内表面更小的明度差，不依赖代码前景限制下的块表面。
   深浅色强度参考改造前 Live 的区分度，不能反复叠加混色比例代替校准。
   用可感知明度差设置区分下限，以前景可读性设置偏移上限；极黑背景不能机械
   固定低比例，否则混合结果仍几乎是黑色，应提高弱表面的明度差或辅以轻边界。
   极白背景向深色混合，已有明显色差时限制继续偏移。
4. 普通正文、标签和按钮文字按实际承载面检查 4.5:1；必要的操作图标、焦点和编辑
   边界检查 3:1。这些参考 [WCAG 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
   与 [非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。
   不把“块表面与文档背景必须 3:1”当作规则，否则淡背景会变成强烈色块。
5. 纯装饰分隔线以约 1.4–1.8:1 为视觉试配目标，表格网格可略高，最终用截图确认。
   这是项目的候选视觉强度，不是 WCAG 阈值；若某条线是理解结构或操作所必需，
   应提升至 3:1 或增加其他明确线索，不能套用装饰线强度。
6. 同一派生角色使用不透明最终色值，或保证在正确父背景上合成；不能将同一个半透明
   线色叠在不同背景后宣称颜色一致。表格、代码块内分割线都要按自己的承载面检查。
7. 块按钮常态不铺独立菜单底色；悬停增强中性前景并加轻底色，深色表面变亮、浅色
   表面加深，顶部工具按钮和底部展开/折叠动作共用此规则。按下略强，键盘焦点
   有清晰轮廓。图标与相邻文字同源。块按钮展开的真正菜单仍回到 UI 菜单配色。

## 需要保留的语义与补充范围

- **内容强调与脚注**：标题、列表、目录、链接、菜单匹配继续共用内容强调体系。
  脚注和内容标签的淡背景保留相应强调来源，在新 B 上合成并重新校正前景，
  不能一律改成中性块背景。
- **选区、搜索命中、diff、警告及成功状态**：保留各自语义输入；若与新 B 对比不足，
  只调整最终前景/透明度/边界，不将它们当作普通正文分隔线。
- **活动行**：普通文档活动行和块内活动行要在各自底色上派生，避免进入代码块后
  活动行突然变成另一色系；与搜索和 diff 重叠时维持既有优先级。
- **补充检查**：行内代码、键盘标签、表格表头/浮动表头、引用边线、列表引导线、
  图片占位及错误区、代码语言标签、折叠摘要和底栏、嵌套源码区行号、分栏分隔线。
  位于内容中的占位面复用块表面，错误图标/文字保留危险语义；浮层保持 UI 表面。
- **读写状态一致**：公式、Mermaid、frontmatter、表格在阅读/源码编辑/分栏/折叠之间
  不应出现来源不明的底色跳变；背景改变不调整布局、字号或文档高度。

## 自定义背景与源码前景的边界

Source 语法前景属于宿主主题，八项配置中没有独立的正文前景输入，因此不能承诺
任意 HEX 文档背景都与所有语法 token 对比充分。尤其是在深色模式输入纯白背景时，
不能仅靠派生代码块表面解决普通源码文字的可读性。

建议保持用户输入及原生语法色，设置页对与当前明暗/普通正文前景明显不适配的
自定义背景显示非阻塞说明，建议切换模式或调整背景；提供恢复默认入口。
不静默切换明暗，不给每个 token 重新染色，也不自动把用户的背景改成别的 HEX。

块表面应优先选择不削弱现有代码前景对比的混合强度。用已准备好的代码配色检查，
若没有协调且足够可读的派生结果，保留原主题代码承载面，并用协调的边界与留白
连接到文档背景；将这种例外明确显示在验收结果中。此时保留语法可读性优先于
强制所有大块都共享完全相同的最终底色。普通正文前景不适配仍需要上面的说明。

## 性能与实施顺序

计算放在共同配色入口，组件只引用角色，不逐元素读宿主色、不逐元素混色。
沿用一次动画帧合并输入与按实际基础色缓存结果；缓存只是可重建投影。
代码配色检查复用现有调色板，不在拖动中重跑 Shiki、解析整篇文档或遍历全部 token DOM。
Mermaid 拖动期间先更新可直接投影的背景 CSS；自动保存成功后让受影响图形按包含最终背景的
配色缓存键更新，避免复用旧标签底色，也避免每个取色事件都重新布局图表。

1. **已接入**：第八项配置、默认快照、严格校验、正式外观页、自动保存/重试/重载，
   以及 CSS-only 的默认 Preview 底色同步。
2. **先做 Live 共同角色**：块表面、行内弱表面、正文分隔线、块内按钮状态。
   迁移代码块/Mermaid 外层/公式编辑/frontmatter/表格，截图确定实际强度；
   只将通过验证的派生规则写入界面设计约定。
3. **补边界和模式**：活动行、嵌套编辑、折叠、浮动表头、脚注及错误占位；
   接入背景适配说明和语法配色例外，确认优先级。
4. **按既有范围贯通**：默认 Preview 与导出的共同角色通过样式环境传递，
   验证独立预设隔离。若改变独立预设/导出产品含义，先确认新范围。

## 验收

第一版已接入共同角色、Live 块/行内/表格/frontmatter、块按钮、活动行、嵌套源码
和正文边线；默认同明暗 Preview 以 CSS 同步最终角色，已有样式环境也携带最终值。
独立预设不注入文档派生角色，导出保留其已有页面明暗策略。代码检查复用已准备的
普通文字与注释配色，不能据此宣称所有语法 token 在任意 HEX 背景上均有充分对比。
外观页提供非阻塞的背景/代码承载面说明，拖动不触发 Mermaid 布局，自动保存成功后刷新 SVG。

行内代码、表头与隔行填充按改造前的 Live 区分度校准，默认 Preview 共享最终角色。
基准提交为 `04a97074a2606d15b5477c299d188ebef96c35b4`；行内代码来自固定 DOM 样式记录，
表格填充按该提交的 inset 配色与 Live 表头规则计算。旧 RGB 仅作为区分度证据，
不直接用于新主题，也不另增加配置项。

| 旧 Live 模式 | 文档 / 行内代码 / 表格填充 | 行内与文档 | 表格与文档 | 行内与填充行 |
| --- | --- | --- | --- | --- |
| 浅色 | `#FFFFFF` / `#E6E8EB` / `#F8F9FA` | 1.23:1 | 1.05:1 | 1.16:1 |
| 深色 | `#1F1F1F` / `#44484D` / `#252628` | 1.79:1 | 1.09:1 | 1.64:1 |

块表面使用已选择的明暗档位：深色「轻柔层次」保留原 OKLab 底色差的 75%，
浅色按后续反馈改为保留 60%，暖浅色和冷深色分别沿用对应档位。
原块表面基准为 `documentLayer(dark ? 0.10 : 0.055, 1.12)`，再与文档底色回混；
这是不透明最终色的混合比例，不是 CSS 透明度，也不是对比比值乘以百分比。
1.12 只约束原基准，不重新施加到减弱后的块表面；混合后继续沿用文字与代码前景保护。
代码块、Mermaid 外层、块状公式编辑区及 frontmatter 保持共用块角色，因此 frontmatter
同步减淡。按钮前景、悬停、边界继续按新承载面做已有校正，不改这些角色的派生参数；
行内代码、表头及隔行填充保持独立校准。

新派生以这些表面差为目标，用现有 OKLab 混色寻找接近目标的颜色，并保持文档底色系。
行内代码在填充行上保留独立底色和轻内边线。深浅色分别校准，文字可读性仍作为偏移上限；
表格直接从文档底色派生，避免代码主题回退导致填充消失或改变强度。
frontmatter 外框与内部行列线使用单独的块边界派生角色，深浅色均增强；表格边线仍弱。
浅色块内按钮的常态中性前景适度向块底色回混，降低默认强调；悬停/焦点前景独立计算，
保持现有增强强度。深色与高对比模式维持原强度，常态仍受文字可读性下限约束。
浅色常态只按自身块底色校正，不让已有独立前景的悬停/按下底色限制其减弱幅度。
按后续视觉反馈，浅色块内常态附属操作文字/图标使用较弱的 3.5:1 视觉下限；
这是该角色的局部弱化例外，不宣称满足小字的 WCAG 4.5:1 要求。
正文、普通 UI 文字、悬停/焦点和高对比模式维持各自原有下限。
文字可读性限制使用有界收敛保留最强的可读底色，避免直接减半使增强后的行内背景反而更淡。
属性名列的底色复用块内交互表面，避免混入旧 UI 的冷灰色边线。

浅深两套配置都覆盖近中性背景、暖/冷色背景、接近纯白/纯黑背景，以及明暗反转
导致的前景不适配情形。检查普通、悬停、按下、键盘焦点、阅读/编辑和 Source 切换，
包括按钮、语言标签、网格/分割线及多层嵌套后的实际对比。

复用既有配置、正式外观页、主题继承、文档背景与渲染块测试，不新增逐行镜像测试。
每个连贯迁移组按普通快速门禁及必要领域的定向检查验证；该配色逻辑/配置改动不走
轻量 UI 路径。截图注明编号与输入配色。长文档、完整浏览器矩阵和耐久长测另行授权。
